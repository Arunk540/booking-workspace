# docs

| Where | What | Loaded |
|---|---|---|
| `CLAUDE.md`, `.claude/rules/` | workspace map, how to find code, hard rules | every session |
| `services/<svc>/CLAUDE.md` | verified build/test, files that change together, traps | in that service's checkout (`CLAUDE.local.md` symlink) |
| `docs/generated/<svc>/entry-points.md` | Kafka / REST / Temporal entry points with file:line | on demand; generated by `ctx.js index`, never committed |
| `.asta-context/repos/<repo>/{runtime,contracts,integrations,operations}/` | why a flow works the way it does | on demand, by path from `ctx find` |
| `docs/specs/<ticket>.md` | the approved plan for one change: files, acceptance commands | by the legs of that task |
| `docs/adr/` | decisions that outlive one change | on demand |

## Keeping it true

- `node .asta-context/ctx.js verify` checks every path, class name and Maven command named in the files above against develop.
  `--run` also executes each service's `verify` block. The night refresh runs both before it pushes anything.
- Code wins over docs. A leg that finds a mismatch lists it; the refresh fixes the doc.
- Budgets: root ≤ 2.6k chars, rules ≤ 1.8k total, each service ≤ 3.2k. A new line has to replace an old one.
- `lessons.md` files are the inbox: legs append there. The refresh promotes each lesson to the strongest thing that fits
  (hook or test > `ctx verify` check > a service-file line > a doc) and then removes it from the inbox.

## Measuring

`node .asta-context/eval.js run <gold.jsonl>` scores `ctx find` against files that real merged PRs changed.
The gold set is built from PR titles and lives outside this repo. `eval.js build` makes it.
